# Competitive Analysis

> **语言规则**：默认跟随用户输入语言。稳定 artifact type 使用 `COMPETITIVE_ANALYSIS`，详见 `../../references/language-policy.md`。

## 目标与边界

以已确认的产品定义为锚点，产出能支撑产品取舍的竞品分析，而不是资料汇编或执行日志。研究可以广泛，但正式报告只写与产品判断有关、证据充分、能够指导方案的信息。

单品分析固定使用四个维度：

- **基础**：给谁用、解决什么问题、为什么选择它、发展阶段、商业模式和竞争壁垒。
- **功能**：能力全景、重点功能、输入输出、流程、完成标准和能力边界。
- **体验**：用户如何理解、进入、完成核心任务并从失败中恢复。
- **增长**：可观察的获客、激活、留存、传播和付费边界。

AI 探针仅是功能维度的条件分支，用于验证 AI 功能的外部表现和边界，不构成第五维度，不推断不可验证的内部架构、性能或商业可用性。

## 强制上游门禁

开始前必须找到并读取由 `$define-product` 产出的、状态已确认的 `PRODUCT_DEFINITION`，其中至少明确：产品定位、目标用户或角色、核心问题、价值机制和产品边界。

- 缺失、未确认或与用户当前说法冲突：停止竞品分析，先完成或更新 `$define-product`。
- 存在多个定义：列出产品名、路径、状态和确认日期，让用户明确选择主产品；不得自行猜测。
- 主产品未确认前不联网调研。
- `USER_PERSONA` 为可选上游；存在时复用，不静默改写。

确认主产品后，记录本次产品决策、目标用户/场景、证据截止日期和交付物边界。

## 两类产物

- **正式报告 `COMPETITIVE_ANALYSIS`**：面向领导和产品决策者，只保留结论、关键证据、限制和建议；直接进入文档门户。
- **研究底稿 `COMPETITIVE_ANALYSIS_WORKLOG`**：保存门禁、证据索引、材料批次、测试协议、冲突、待办和恢复点；不进入门户。

默认文件：

```text
docs/Competitive-Analysis-{产品名}-{YYYYMMDD}.mdx
docs/Competitive-Analysis-{产品名}-{YYYYMMDD}.research.md
```

市场分析完成即创建正式 MDX 与底稿；后续节点持续更新同一正式文件和同一稳定 slug，不在最后再把 Markdown 转换一次。

## 文档发布硬门禁

正式文档的创建、更新和门户发布必须遵循 `$document-publisher`（若宿主未暴露该名称，则读取并遵循本插件的 `document-publisher` Skill）定义的 Authoring Contract。业务 Skill 直接产出可发布的 MDX/DSL；publisher 不替业务 Skill 补写内容，也不把普通 Markdown 自动升级为成品。

每次正式写入前还必须读取 [09-report-writing-and-visual-design.md](references/09-report-writing-and-visual-design.md)，在底稿完成当前节点的页面蓝图，然后通过 `$document-publisher` 直接创建或更新最终 `.mdx` 与门户条目。不得创建中间 Markdown 文档、不得在最后做 Markdown→MDX 转换，也不得仅以“标题 + 段落 + 表格”或无差别卡片化完成写入；组件必须解决明确的阅读任务。

每个要求写入正式报告的节点都必须完成以下闭环：

1. 在底稿写出 `读者任务 / 核心判断 / 信息关系 / MDX 组件或图形 / 选择理由 / 证据落点` 页面蓝图；此处不准备另一份 Markdown，也不设计 Markdown 中间稿；
2. 调用 `$document-publisher`，将已确认结论直接写入最终 `.mdx`，过程信息写入 `.research.md`；
3. 通过 `$document-publisher` 使用稳定 slug 创建或更新门户条目；
4. 执行 publisher 要求的结构、资源和门户校验；
5. 从门户产物回读标题、节点内容和状态，确认本次更新真实可见；
6. 记录 `页面蓝图 / 文件写入 / 门户更新 / 校验 / 回读` 五项结果。

五项全部通过后，节点状态才能标记为“已完成”并进入下一节点。若用户明确禁止发布，则停在当前节点并标记“内容已确认，待授权发布”；不得绕过门禁或假装完成。

只有用户要求打开页面时才安装门户依赖并启动服务。门户模板不得保存本次研究的 mock 内容；研究底稿不得发布。

## 证据规则

始终区分：`【事实】`、`【官方声称】`、`【体验观察】`、`【合理推测】`、`【待验证】`。这些标签用于证据单元、重要判断或性质容易混淆之处，不要求给每句话和每个表格单元格机械加前缀。关键事实附直接来源和检索日期，优先官网、帮助中心、更新日志、价格页、财报、论文和一手访谈。二手资料用于发现线索；可获得一手来源时不得用二手资料替代。

正式报告中的外部证据统一使用 `[S01]`、`[S02]` 格式的稳定引用标记，并关联到整篇文档最底部的“外部来源索引”；同一来源和支撑范围复用原编号，新增来源只追加编号，不因章节重排而重编号。正文不得散落裸链接，也不得按章节重复维护来源清单。A2 竞品范围中的官网链接属于产品入口，可以直接链接产品名称，不作为证据裸链接。索引至少记录来源标题、发布主体、发布日期、URL、检索日期、适用对象与支撑范围。研究过程中的候选来源、未采用材料和完整证据明细只进入底稿。

“机制存在”不等于“效果有效”，“未测”不等于“没有”，“未知”不等于 0 分。用户停止补充材料时按当前证据收口并保留限制。

## 唯一端到端流程

以下是唯一运行流程。参考文件解释节点内怎么做，不得再定义第二条流程、改变顺序或绕过门禁。

### A0 任务启动

**前序输入**：通过强制上游门禁，并由用户确认主产品。

**本节点任务**：锁定产品决策、用户/场景、证据窗口、已有材料和交付范围；创建研究底稿与节点状态板。

**完成门禁**：主产品和任务边界均已确认，底稿可恢复；通过后进入 A1。

### A1 市场分析

**前序输入**：A0 已完成。

**本节点任务**：广泛调研，最终只提炼市场规模、市场机会、上下游产业分布，并形成市场判断。市场定义仅作开篇口径说明。数据关系优先用 `antv-infographic-syntax` 表达，不用表格堆数据。详见 [01-a0-a2-start-market-and-competitor-selection.md](references/01-a0-a2-start-market-and-competitor-selection.md)。

**正式写入**：先向用户展示市场规模、市场机会、上下游产业分布和市场判断，处理修订并取得明确确认；再创建正式 MDX，写入本节点已经确认的市场内容，同时更新底稿。执行完整文档发布硬门禁。用户未确认时不得写入或进入 A2。

**完成门禁**：三类分析足以说明机会和产品位置；重要数字有口径、时间和来源；市场判断能指导竞品检索；门户已更新并回读。通过后进入 A2。

### A2 竞品检索与确认

**前序输入**：A1 已完成且门户写入通过。

**本节点任务**：基于市场结构和替代关系提出 2–5 个候选。必须按 [01-a0-a2-start-market-and-competitor-selection.md](references/01-a0-a2-start-market-and-competitor-selection.md) 判断直接、间接或潜在竞品：直接竞品争夺同一用户的同一核心任务；间接竞品以不同路径满足同一上位目标并争夺预算、时间或流程位置；潜在竞品当前替代性有限，但已具备相邻进入能力和可验证的进入信号。不得只因同赛道、知名、功能相似或出现在行业榜单中就纳入。候选调研至少覆盖图标、官网、产品定位、与主产品的重合点和差异点、发展阶段，并以所属主体、对象形态、融资、团队、发展历程和行业报告/第三方数据作为判断证据。独立产品和母产品内部功能必须明确区分。展示候选后必须询问用户是否还有其他竞品需要补充；如有，按同一口径检索新增对象、并入候选范围后再次询问，直到用户明确表示没有其他补充。随后展示最终竞品范围并取得用户明确确认，不得以沉默或上下文推定确认。

“2–5 个”只约束首次候选批次，不限制用户补充后的最终范围。最终范围超过 5 个时，必须提示调研工作量和分批分析方式，再由用户确认最终分析范围。

**正式写入**：仅在用户明确确认最终范围后，写入“竞品范围”表格，字段固定为：`图标｜产品名称｜官网链接｜产品定位｜重合点｜差异点｜发展阶段`。同时让用户确认“最终分析范围”是否包含主产品；默认不强制分析主产品，只有被用户纳入最终分析范围的对象才是最终交付必选对象。图标必须使用可稳定读取的本地门户资源；完整检索过程、候选淘汰理由及融资、团队、发展历程、行业报告/第三方数据等支撑资料写入底稿，不展开到正式报告。更新门户、校验资源并回读。

**完成门禁**：用户已明确表示无其他竞品补充，最终竞品集合与对象边界已被明确确认，表格及图标资源已通过门户校验并完成回读；通过后进入 A3。

### A3 单品分析循环

**前序输入**：A2 已完成；可选对象包括主产品和 A2 已确认的外部竞品，最终交付对象以 A2 记录的“最终分析范围”为准。

**本节点任务**：首次进入时，向用户列出主产品与已确认外部竞品及其分析状态，明确询问第一轮分析本品还是哪一个外部竞品，不得自行决定。用户选择后，为本轮锁定唯一对象标识、官方名称、对象形态、产品入口、版本、账号、地区、设备、决策目标和证据边界，并确定正式报告中“单品分析 / {当前产品}”的稳定章节路径；A3 只登记路径，不提前创建空章节或写入分析正文。内部功能须分开母公司级证据与功能级证据。

**循环约束**：B1–B6 构成该对象的一次完整分析循环。整个 B 循环只能研究 A3 锁定的同一对象；用户中途提到其他产品时，只记录到待分析队列，不得切换当前对象。B1–B6 的正式内容必须持续写入该对象的同一专属章节，不得散落到其他产品或通用章节。

**流转门禁**：本轮对象和边界经用户确认后进入 B1；对象通过 B6 后必须通知用户当前对象分析完成并返回 A3。A3 重新读取全部对象状态，由用户选择继续分析下一个对象、补齐当前对象，或进入 A4 阶段性/最终收口。A3 不创建未分析对象的空章节；至少一个对象通过 B6 后才可进入 A4。

### B1 基础分析

**前序输入**：A3 已锁定本轮唯一分析对象，并已确定该对象的稳定专属章节路径。

**本节点任务**：围绕当前锁定对象联网检索并补齐证据，形成产品定位、发展阶段与关键里程碑、主要/次要/探索中的商业模式，以及网络效应、数据壁垒、转换成本、品牌认知、技术壁垒、规模效应六项 0–5 分证据化评估。先向用户展示基础分析结论、证据与限制，处理用户提出的修订；详见 [02-b1-foundation-analysis.md](references/02-b1-foundation-analysis.md)。

**正式写入与门禁**：只有用户明确确认本轮基础分析后，才写入“单品分析 / {当前产品} / 基础分析”，并执行门户更新、校验和回读。未确认时停留在 B1，不得提前写入或进入 B2；全部通过后进入 B2。

### B2 功能分析

**前序输入**：B1 已完成。

**本节点任务**：围绕当前锁定对象完成证据采集、功能架构、关键用户旅程、重点与差异功能、功能边界及技术实现判断。功能总览优先使用 AntV mindmap 形成主次层级；关键旅程组合使用 AntV 阶段总览、Steps 子路径、Mermaid 分支与相邻截图。网站产品优先从官网与公开页面自行调研；需要登录时说明调研范围，由用户自行登录并授权使用当前浏览器会话。App 产品先依据 B1 与公开资料提出初步产品逻辑，再向用户索取首轮截图，并要求同时提供版本与系统信息。每轮材料到达后必须更新覆盖台账，检查入口、功能理解、用户旅程和延伸能力，不能从截图空白处自行猜测；据此提出下一轮最小采集范围。若发现 AI 入口，B2 要提供能打通核心旅程的最小提示词，但不在本节点评分。常规最多三轮，三轮后仍有会改变核心判断的明显缺口时，只能说明理由并向用户申请一次额外采集。用户提供的重复或超范围材料由执行者自行去重、归类和判断价值。详见 [03-b2-feature-analysis.md](references/03-b2-feature-analysis.md)。

**正式写入与门禁**：先向用户展示功能分析结论、证据覆盖和剩余限制；用户明确确认后，写入“单品分析 / {当前产品} / 功能分析”。正式报告至少包含功能结构图、关键用户旅程、重点与差异功能、代表性截图证据、技术实现判断及限制；逐轮采集计划、全量截图索引、重复材料和完整覆盖台账留在底稿。执行门户更新、资源校验和回读，全部通过后判断是否进入 B3；未确认或仍有阻断性缺口时停留在 B2。

### B3 AI 探针（条件节点）

**前序输入**：B2 判定核心旅程中存在面向用户的 AI 理解、生成、推荐、规划、代理行动，或 AI 对结果、决策、交易有实质影响；功能入口、任务与产品边界已明确。

**本节点任务**：覆盖意图理解、多任务拆解、多轮记忆、响应速度、首次可用率、个性化、核验通过率/幻觉率、完整性/任务完成率、过程可视化、结果可编辑和交易闭环 11 个方向。概率类方向每项冻结 4–5 条指令，定性类每项只保留 1 条代表指令。先向用户展示并确认测试协议；确认后才将测试方向、指令原文和预期表现写入正式文档。用户提供截图后逐条或按用户本次提交批次回填实际表现、点评、评分和截图。详见 [04-b3-ai-probe-testing.md](references/04-b3-ai-probe-testing.md)。

**正式写入与门禁**：计划写入、每个用户提交批次的证据回填和最终收口都必须执行门户更新、校验和回读；用户逐条提交时批次即为一条，用户一次提交多条时合并为一次更新，不机械逐 Case 重复发布。全部测试后最多发起一轮必要补充，并根据新截图回看 B2 遗漏。用户可部分完成后暂停并进入 B4；恢复时必须先通读整份正式文档和研究底稿，再从未完成 Case 续写。若不满足触发条件，将 B3 标记“不适用”并进入 B4。

### B4 体验分析

**前序输入**：B2 已完成；若涉及 AI，B3 已完成、明确不适用，或已按用户要求暂停并把状态写入门户。

**本节点任务**：先复用 B2、B3 的截图与实测记录，审计第一印象、Onboarding、核心路径、信息架构、视觉设计、错误处理六个板块的证据完整性。只有缺口会改变体验判断时才定向补充；补充完成后形成“总分析 + 逐板块分析”，每个板块明确亮点、缺点、用户影响、产品启示和证据限制。随后反向检查 B2、B3，发现功能结构、旅程、AI 表现或证据映射需要调整时，必须同步修订原板块。详见 [05-b4-experience-analysis.md](references/05-b4-experience-analysis.md)。

**正式写入与门禁**：用户确认后调用 `document-publisher` 写入 B4；如 B2、B3 有修订，必须同步更新并回读核验。门户闭环通过后进入 B5；关键体验判断仍无证据且用户未接受受限结论时，设置 `node_status: 等待材料` 并保存恢复点，不得推进。

### B5 增长分析

**前序输入**：B4 已通过门禁，且 B4 反向检查发现的 B2、B3 修订已写入并完成回读核验。

**本节点任务**：先复用 B1–B4 的公开资料、截图、路径和体验结论，审计获客、转化、留存、传播和定价五个板块的证据完整性。只有缺口会改变增长判断时才定向补充；补充完成后形成“总分析 + 逐板块分析”，每个板块明确机制与路径、亮点、缺点、效果证据、产品启示和证据限制。随后反向检查 B1–B4，发现商业模式、功能结构、AI 结论或体验判断需要调整时，必须同步修订原板块。只分析可观察机制及可靠效果证据，不从页面存在推导增长有效。详见 [06-b5-growth-analysis.md](references/06-b5-growth-analysis.md)。

**正式写入与门禁**：用户确认后调用 `document-publisher` 写入 B5；如 B1–B4 有修订，必须同步更新并回读核验。门户闭环通过后进入 B6；核心增长机制仍无证据且用户未接受受限结论时，设置 `node_status: 等待材料` 并保存恢复点，不得推进。缺少效果数据不阻止机制分析收口，但效果判断必须保留为待验证。

### B6 单品完整性审阅与交付门禁

**前序输入**：B1–B5 已完成或明确标记条件不适用/受限，且 B5 反向检查产生的前序修订已写入并完成回读核验。B3 仍为用户主动暂停时只能尝试阶段闭环；除非用户明确接受受限结论，且未完成探针不会改变本次决策，否则不得达到“单品整体闭环”。

**本节点任务**：全面回读当前对象的 B1–B5、证据与门户正文，确认竞品信息完整，消解跨模块矛盾，并形成四维单品总结。同时检查正式内容模块是否齐全，标题、术语、图文关系和表达是否清晰、易读、无歧义，过程内容是否已清除，正文引用是否能定位到文末外部来源索引。详见 [07-b6-a4-closure-and-comparison.md](references/07-b6-a4-closure-and-comparison.md)。

**正式写入与门禁**：直接修订受影响的原模块并写入四维总结；信息完整性、证据、冲突、内容结构、语言、图形、引用、门户渲染、校验和回读全部通过后，才标记真实闭环等级。只有达到 `closure_level: 单品整体闭环` 时才通知用户“当前对象的竞品分析已完成”；阶段闭环只能说明对应成果已收口及其限制。随后解除对象锁定并返回 A3；未通过时不得宣告完成。

### A4 单品分析阶段收口与横向比较

**前序输入**：至少一个对象通过 B6，且用户在 A3 明确选择进入分析收口。

**本节点任务**：重新读取 A1、A2、`PRODUCT_DEFINITION`、全部对象状态、已完成的 B1–B6、限制、恢复点、当前报告和来源索引。至少一个对象完成时可以形成阶段性收口：已完成对象单列完整内容，部分完成对象只保留已通过门禁的内容，未分析对象只在“对象完成度总览”显示名称、类型和状态，不创建空章节或占位正文；写入并保存恢复点后返回 A3。只有 A2 最终分析范围内的全部对象都完成 B6，才进行最终收口和符合条件的横向比较。

**正式写入与门禁**：阶段性收口完成门户写入、校验和回读后返回 A3，不宣告最终交付。最终收口写入四维比较、可借鉴、不可照抄、差异化和行动建议后进入 C1；未知、未测和不可比项不得计 0 分，未达到单品整体闭环的对象不得进入正式矩阵。

### C1 最终成稿与交付

**前序输入**：A2 最终分析范围内全部对象均已完成 B6，且 A4 最终比较与建议已通过门户门禁。

**本节点任务**：按与用户逐模块确认的报告契约重新编辑全文；模块服务读者理解和产品决策，不机械均分篇幅。全文检查完成后最后生成“竞品分析结论”，再将其放到报告正文最前面；正文外部引用统一指向文档最底部的“外部来源索引”。详见 [08-c1-final-report.md](references/08-c1-final-report.md)。

**正式写入与门禁**：删除过程性内容和重复信息，校验证据、图形、链接、暗黑模式与门户结构；最终门户更新、校验和回读全部通过后才宣告交付完成。

## 状态与恢复

研究底稿维护：

`对象 | 当前节点 | node_status | probe_status | object_status | closure_level | 本轮目标 | 已完成产物 | 阻塞缺口 | 下一动作 | 门户写入状态`

四类状态不得混用：`node_status` 仅使用 `未开始 / 进行中 / 等待材料 / 部分完成 / 已完成 / 不适用 / 暂停 / 已停止`；`probe_status` 仅使用 `未触发 / 计划待确认 / 计划已写入 / 执行中 / 部分完成／暂停 / 已完成 / 受限停止 / 不适用`；`object_status` 仅使用 `未分析 / 分析中 / 部分完成 / 已闭环 / 受限停止`；`closure_level` 仅使用 `未闭环 / 专题闭环 / 单维闭环 / 单品整体闭环`。切换对象时暂停原对象并保存恢复点；不得让两个对象的 `object_status` 同时为“分析中”。

状态关系必须一致：只有 `closure_level: 单品整体闭环` 才能设置 `object_status: 已闭环`；`专题闭环` 或 `单维闭环` 对应 `object_status: 部分完成`；外部限制导致停止时使用 `object_status: 受限停止`，同时保留已经真实达到的 `closure_level`。节点是否完成只写入 `node_status`，不得用对象状态或闭环等级代替。

每个节点对用户报告：`节点结论 | 未覆盖范围 | 门禁结果 | 门户写入结果 | 下一节点`。用户说“继续”仅表示执行当前节点已说明的下一动作，不等于同意跳过门禁。

## 下游复用

下游读取 `COMPETITIVE_ANALYSIS` 时必须保留证据日期、来源、测试条件、信息性质与待验证状态；不得把旧价格、官方声称或推测升级为当前事实。只有能追溯到证据且适配主产品定位和用户的建议，才能进入 BRD、PRD 或路线图。
