# B1 基础分析

本参考只负责单品的**基础维度**：产品定位、发展阶段、商业模式和竞争壁垒。功能、体验和增长机制分别由后续阶段处理。

## 先定义证据记录

每条关键证据至少记录：`结论单元 | 信息性质 | 来源标题 | 来源主体 | 发布/更新日期 | 检索日期 | URL或材料位置 | 适用对象 | 备注`。

来源优先级：

1. 官网、产品页、价格页、帮助中心、更新日志、财报、论文和监管披露；
2. 可核验的一手访谈、演示或实际产品体验；
3. 有明确原始出处的专业媒体与数据库；
4. 社区评论和社交内容，只用于体验线索，不用于证明市场规模或内部能力。

同一结论存在冲突时并列展示来源、日期和口径，不静默选择。当前页面已经删除、登录受限或无法访问时记录限制。

先在研究底稿维护《信息覆盖度速览》，维度包括产品定位与人群、发展阶段、商业模式和六项竞争壁垒。使用 ✅ 表示信息充分、⚠️ 表示部分覆盖、❌ 表示几乎无公开信息。覆盖度用于决定是否补充检索，不直接写入正式报告；存在缺口时继续形成可支持的判断，并明确限制。

默认优先使用检索日往前一年内发布或更新的公开资料，其中价格、功能可用性、模型版本和团队信息应优先核对当前一手页面。确有必要时可以引用更早证据，但必须写明日期、使用原因并提醒“当前状态可能已变化”。每个关键单元格至少能回到一个直接来源或明确的体验记录。

## 当前对象与章节边界

B1 只能分析 A3 当前锁定的一个对象。开始检索前，从状态板回读对象唯一标识、官方名称、对象形态、官方入口和证据边界；任何证据必须注明适用对象。出现另一产品的信息时，只作为比较背景或待分析线索记录，不得把它的结论写入当前对象。

正式报告在“单品分析”下为每个对象维护独立章节，稳定路径为：

```text
单品分析
└── {对象官方名称}
    ├── 基础分析
    ├── 功能分析
    ├── 体验分析
    ├── 增长分析
    └── 四维总结
```

A3 只登记该路径，不创建空章节。B1 获得用户明确确认后才创建或更新当前对象的“基础分析”，不得创建无产品归属的通用“基础分析”，也不得覆盖其他对象已经确认的章节。

## 每个分析对象的基础档案

确认竞品集后，每个进入单品流程的分析对象（竞品或后来补充分析的主产品）必须使用以下四个一级模块，且保持相同顺序：

### 产品定位

- **给谁用？** 描述具体目标用户画像，包括角色、场景、行为、能力或资源条件、付费者与使用者是否一致；不要只写“年轻人”“企业用户”等宽泛标签。
- **解决什么问题？** 用一句话概括其核心痛点，必要时另列次要任务。
- **凭什么选择它？** 说明差异化价值，以及相较直接竞品、间接替代和不使用任何产品的区别。

### 发展阶段

- 在初创 / 增长 / 成熟 / 转型中给出阶段判断，并附判断日期和证据；
- 按时间顺序列出足以解释阶段变化的关键里程碑，不为凑数量收录无决策价值的事件；
- 融资、团队及规模变化作为阶段判断的支撑信息。产品内部功能与母公司信息必须分层记录。

### 商业模式

- 从广告、佣金、买卖差价、SaaS 订阅、一次性直接付费、增值服务、金融收益中选择适用项，也可补充有证据的其他模式；
- 明确区分主要商业模式、次要商业模式和仍在探索的商业模式；
- 收费方式、付费方、收入机制或商业化成熟度缺少证据时标记 `【待验证】`。

### 竞争壁垒

- 按下方六项壁垒逐项进行 0–5 分评估；
- 每项必须同时给出直接证据或可追溯数据，以及一句评分理由；
- 引用行业报告或第三方数据时保留原始口径、日期、地域和估算方法。

## 六项壁垒评分

对每个分析对象逐项给出 0–5 分、证据和一句判断理由：

| 维度 | 判断问题 |
|---|---|
| 网络效应 | 用户越多，其他用户获得的产品价值是否提高？ |
| 数据壁垒 | 持续积累的数据是否改善产品、难以复制，并形成反馈闭环？ |
| 转换成本 | 用户迁移时是否损失数据、关系、流程、集成、学习投入或经济权益？ |
| 品牌认知 | 是否占据清晰品类心智，并影响用户搜索、信任或默认选择？ |
| 技术壁垒 | 技术实现、工程可靠性、算法、专利或专有基础设施是否难以复制？ |
| 规模效应 | 规模是否带来单位成本、采购、分发、供给或资本效率优势？ |

统一评分锚点：`0=没有可观察壁垒；1=很弱；2=有限；3=中等且已形成；4=强；5=行业领先且难以复制`。证据不足时写 `【待验证】`，不得把未知记为 0。分数用于逐项比较，不默认相加成总分；若需要总分，必须先确认各维度权重和适用性。

## 用户确认与阶段交付

正式页面使用 `Profile + InfoGrid + 商业模式分组 + 壁垒图与核验表 + 关键判断` 的组合，具体字段和视觉门禁遵循 [09-report-writing-and-visual-design.md](09-report-writing-and-visual-design.md) 的 B1 蓝图。开始写入前先在底稿完成页面蓝图，再通过 `document-publisher` 直接更新最终 MDX。

检索和判断完成后，先向用户展示当前对象的四项基础结论：产品定位、发展阶段、商业模式、竞争壁垒评分。每项同时给出代表证据、信息性质和会影响判断的限制。用户要求修订时，继续在 B1 补充或调整；不得把“已展示”视为“已确认”。

只有用户明确确认后，才执行正式写入。若用户只确认部分内容，已确认与待确认项继续留在 B1 状态中，不得以部分确认绕过本节点门禁。

每个分析对象分别按“产品定位、发展阶段、商业模式、竞争壁垒”四个模块提炼进正式报告的单品章节，不在本阶段提前生成横向比较或最终行动建议。基础商业模式说明公司如何捕获价值；价格套餐、付费墙和升级触发留给增长层分析。

完整证据表、信息覆盖度、冲突、门禁状态和待验证项写入研究底稿；正式报告只保留支撑定位、阶段、商业模式和壁垒判断的代表证据，以及会改变结论的限制。未知评分写 `【待验证】`，不得留空或计为 0 分。

完成写回后同步更新状态板，并执行 `SKILL.md` 的文档发布硬门禁。只有用户已经明确确认，四个模块均有证据覆盖或明确待验证状态，关键基础缺口已处理或降级说明，且当前产品专属章节已写入、门户已更新、校验与回读通过时，B1 才设置 `node_status: 已完成`；否则按实际情况设置 `node_status: 部分完成` 或 `node_status: 等待材料`。B1 未通过门禁时不进入 B2。
