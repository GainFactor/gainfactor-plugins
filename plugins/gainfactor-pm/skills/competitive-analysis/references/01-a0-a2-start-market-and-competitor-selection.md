# A0–A2 任务启动、市场分析与竞品检索确认

本参考依次解释主流程 A0、A1、A2 内部怎么做。节点顺序、门户门禁和状态定义以 `SKILL.md` 为唯一准则。

## A0 任务启动

### 前序输入

- 存在状态已确认的 `PRODUCT_DEFINITION`；
- 用户明确选择本次主产品；
- 产品定位、目标用户或角色、核心问题、价值机制和边界完整。

### 本节点任务

记录本次要支持的产品决策、目标用户与关键场景、地域与证据截止日期、已有资料、明确不研究的内容和交付位置。把材料拆成“已确认 / 待核实 / 未覆盖 / 相互冲突”。只追问会改变研究对象、市场口径或产品决策的问题。

### 完成门禁

任务范围能够用一句话复述，且当前任务已明确下一步。未满足时不进入联网市场研究。

## A1 市场分析

### 分析目标

市场章节不是行业百科，也不是标准咨询框架展示。它只帮助决策者回答：市场有多大、机会在哪里、价值链如何运转、主产品应站在什么位置。

联网研究可以广泛探索政策、技术、资本、供需、用户变化和竞争动态，但正式报告只保留能改变上述判断的信息。不要为了形式完整而逐项输出 PEST，也不要平均分配篇幅。

### 市场口径说明

用一段简短开场定义研究市场、地域、用户、场景和产品形态边界，说明该口径为何适用于本次决策，以及与相邻市场最容易混淆的边界。这是数据解释前提，不扩写成大章节。

### 市场规模

研究总量、增速、结构或渗透率中真正能说明机会的关系。关键数字保留指标口径、地域、年份、数值/币种、来源、发布日期、测算方法或限制、检索日期。

优先采用近一年发布或更新的数据；历史数据仅用于趋势。数字冲突时先检查口径，不强行平均。

- 时间趋势：优先 AntV `chart-line-plain-text`；
- 类别或细分比较：优先 `chart-bar-plain-text` 或 `chart-column-simple`；
- 份额关系且总量确为 100%：可用 `chart-pie-plain-text` 或 `chart-pie-donut-plain-text`；
- 图后解释数据范围、变化原因、产品含义和限制。

禁止用大表格罗列市场数字。数据不足以形成可靠图形时使用叙述并明确缺口。

### 市场机会

只写能指导产品方案的机会，例如未满足需求、结构性增长、供给缺口、流程变化、新渠道或新能力带来的产品窗口。每个机会说明：谁的什么问题正在变化、证据、为什么是现在、与主产品的关系、主要约束。

有清晰优先关系时，从 `document-publisher` 注册表选择具体的 `list-waterfall-*` 或 `list-grid-*` 模板；只有横纵轴有真实测量基础时才使用象限。不得把模板族名称直接写入 DSL，也不得虚构评分制造确定性。

### 上下游产业分布

识别价值、数据、流量、内容、供给、交易或服务如何流动，重点说明：上游稀缺资源、中游平台或工具、下游用户与渠道、主产品位置、关键控制点、依赖、议价关系和潜在替代。

优先使用 AntV `relation-dagre-flow-tb-badge-card` 或合适的层级/关系图。图形必须突出主产品位置和关键关系，不能只画没有决策意义的流水线。

### 市场判断

综合回答：这是怎样的机会；哪类用户/场景值得优先进入；价值链上应控制、合作或规避什么；哪些替代路径决定后续应找什么竞品；最重要的限制是什么。市场判断是结论，不是第四组平行资料。

### 研究与写作原则

- 调研很多，成稿只写真正相关、有价值、能指导方案的信息；
- 先结论，再用关键证据解释，不按来源顺序写资料摘要；
- 政策、资本或技术信息只有改变判断时才进入正文；
- 数据化关系使用 AntV Infographic，不用表格代替；
- 图形遵循 `$document-publisher` 的 `antv-infographic-syntax` 与 authoring contract；
- 完整来源、口径冲突和未采用材料只在当前任务中临时使用，不写入文件。

### 正式写入与门禁

正式页面结构和图形选择必须遵循 [09-report-writing-and-visual-design.md](09-report-writing-and-visual-design.md) 的 A1、A2 蓝图；写入前在当前任务中完成页面蓝图检查，再通过 `document-publisher` 直接写入最终 MDX 与门户。

A1 完成后立即创建：

```text
docs/gainfactor/{product-slug}/competitive-analysis.mdx
```

正式 MDX 首次写入紧凑元信息、调研目标与边界、市场口径、市场规模、市场机会、上下游产业分布、市场判断和关键限制。证据索引、口径冲突、检索记录、未采用信息和 A2 检索依据仅在当前任务中临时使用。

执行 `SKILL.md` 的文档发布硬门禁。门户未更新、校验失败或回读不一致时，设置 `node_status: 部分完成`，不得开始 A2。

## A2 竞品检索与确认

### 前序输入

A1 已完成，市场判断已经明确主要用户、任务、替代路径和价值链位置，且门户写入通过。

### 候选对象

对象形态分为可独立访问或购买的**独立产品**，以及属于更大产品但有独立入口和任务的**产品内部功能**。对象形态回答“它是什么”，竞品类型回答“它如何与主产品竞争”，两者必须分开。

### 竞品类型与纳入条件

竞品不是“同一行业里值得关注的产品”，而是可能影响目标用户完成任务、分配预算或选择方案的替代对象。先从 `PRODUCT_DEFINITION` 提取主产品的目标用户、核心任务、使用场景、价值结果、付费者和关键资源，再判断替代关系。

#### 直接竞品

同时满足以下条件：

- 面向相同或高度重合的目标用户或购买者；
- 解决相同核心问题，承接同一核心任务或关键场景；
- 用户在真实选型、采购或使用时可能在它与主产品之间直接二选一。

功能形态不必完全一致，但必须存在明确的一对一替代关系。仅界面相似或包含同名功能，不足以判为直接竞品。

#### 间接竞品

满足同一上位目标，但采用不同产品形态、工作流或解决路径，并至少争夺以下一项：

- 同一笔预算；
- 用户完成任务的同一段时间；
- 同一工作流入口或关键位置；
- 同一最终业务结果。

例如软件、人工服务、通用工具、线下流程或自建方案都可能成为间接竞品。若只是上下游依赖、互补工具或合作伙伴，且用户不会用它替代主产品，则不属于间接竞品。

#### 潜在竞品

当前尚未形成稳定替代关系，但同时具备：

- 可迁移的相邻能力，例如重合用户入口、数据、模型/技术、渠道、内容供给或交易关系；
- 可验证的进入信号，例如已发布相关功能、公开路线图、招聘与投资方向、收购、试点或连续的产品动作；
- 一旦进入，将影响主产品的用户、预算、渠道或核心任务。

只有“理论上有能力进入”或“公司规模很大”不能判为潜在竞品。没有进入信号时，记录为市场关注对象，不进入正式竞品范围。

### 排除规则

以下对象默认不纳入，除非能够证明上述替代关系：

- 只因同属一个行业、榜单或关键词搜索结果而出现的产品；
- 仅提供上游能力的供应商、渠道、数据源或基础模型；
- 只与主产品互补、不争夺任务或预算的合作方；
- 只有局部功能相似，但目标用户、核心任务和价值结果不同的产品；
- 已停止运营、无法访问或缺乏现实决策价值的历史产品；
- 没有进入证据的假设性大厂或相邻产品。

同一家公司可以同时存在母产品与内部功能，但只有实际参与竞争的对象进入候选。若竞争发生在内部功能层，不得用母产品整体能力替代该功能的竞争证据。

### 候选组合

一次向用户提出 2–5 个最有决策价值的候选，不为凑齐类型而硬选。存在可靠对象时，候选应优先覆盖直接替代者和至少一种不同路径的间接替代者；潜在竞品仅在进入信号会影响当前产品方案或中期决策时纳入。

每个候选必须写明竞品类型和一条可验证的纳入理由，说明它具体替代哪类用户的什么任务、预算、时间或流程位置。证据不足时标记为“待确认候选”，不得直接写入最终范围。

每个候选至少收集图标、产品名称、官网或产品入口、产品定位、与主产品的重合点和差异点、发展阶段、所属主体、对象形态、竞品类型、入选理由，以及可核实的融资、核心团队、发展历程和行业报告/第三方数据。保留信息层级、日期、来源和待验证项。内部功能使用母公司资料时必须明确标注为母公司级证据。

融资、团队、发展历程和第三方资料用于判断产品定位、发展阶段与竞争能力，不要求在正式报告中逐项铺陈。所有事实继续遵守“事实 / 推断 / 未知”的证据纪律。

### 字段判断口径

- **产品名称**：使用官方名称；若分析对象是母产品内部功能，写作“母产品 · 功能名称”。
- **官网链接**：优先使用该对象的官方产品页；没有独立页面时使用母产品中最接近的官方入口，不用搜索结果页或第三方介绍页替代。
- **产品定位**：回答“为谁解决什么问题”，保持为可比较的一句话判断。
- **重合点**：只写与主产品重合的用户、任务、场景或预算，不罗列全部功能。
- **差异点**：只写会影响用户选择或产品方案判断的关键差异，不提前展开完整单品分析。
- **发展阶段**：使用“初创 / 增长 / 成熟 / 转型”之一，并保留可追溯的判断证据。

### 图标采集

图标来源优先级为：官方品牌资源页 → 官方 Logo 或 App 图标 → 官方应用商店图标 → 官网 favicon。下载为稳定的本地门户资源，同时记录来源 URL、采集日期、文件格式、对应产品或功能，以及是否借用母产品品牌。

若母产品内部功能没有独立图标，使用母产品图标并明确标记为母产品品牌，不自行绘制或推测图标。写入前必须通过 `document-publisher` 的资源校验，禁止依赖不稳定的远程热链。

### 补充与确认循环

1. 首次展示 2–5 个候选及其必要判断信息。
2. 明确询问用户：“是否还有其他竞品需要补充？”
3. 若用户补充对象，按完全相同的字段和证据口径完成检索，并入候选范围；不得只记录一个名称。
4. 更新候选范围后再次询问是否还有补充，直到用户明确表示没有其他竞品需要补充。
5. 展示最终竞品范围，单独请求用户确认哪些对象进入正式分析。
6. 只有用户明确确认后才可写入正式报告并进入 A3；沉默、模糊反馈或仅表示“暂时这样”均不得推定为确认。

确认前不得进入单品研究、登录、截图采集或功能实测。被删除和未确认对象不写入正式报告。

### 正式写入与完成门禁

正式报告新增“竞品范围”，此阶段的语义内容只写一张表格；允许保留章节标题和一句不承载新结论的范围说明，不添加分析型 Callout：

| 图标 | 产品名称 | 官网链接 | 产品定位 | 重合点 | 差异点 | 发展阶段 |
|---|---|---|---|---|---|---|

表格之外不写候选池、检索过程、淘汰理由、融资信息堆叠、团队介绍、发展历程复述或行业报告摘要。这些资料与来源仅在当前任务中用于范围确认；后续需要时重新从正式来源核验。

官网链接必须可点击且指向官方页面；图标必须引用已经落地并通过校验的本地门户资源。更新同一门户条目并回读，确认字段、链接和图标均正确显示。只有用户明确表示无其他补充、明确确认最终范围，且门户写入通过后，A2 才完成并进入 A3。
