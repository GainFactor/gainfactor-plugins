# 输入诊断与研究模式

## 先复用已有信息

识别产品定位、产品阶段、核心机制、画像用途和已有材料。若存在 `PRODUCT_DEFINITION`，提取其中的 `已确认`、`明确排除`、`待定义` 和 `待确认冲突`，不重复询问已回答内容。

必须能用具体、面向产品决策的语言解释：

- 用户进入产品前在完成什么任务，当前完整做法是什么；
- 原方法在哪一步失败或代价过高；
- 谁决定、谁使用结果；
- 产品在何时介入，持续提供什么能力；
- 用户最终得到什么可观察结果；
- 产品依赖哪些平台资源、数据或服务能力。

无法解释“用户在什么背景下产生需求—现在怎样解决—产品准备提供什么帮助—边界是什么”时，不创建虚拟用户。一次最多追问 2–3 项会改变分析方向的信息，不要求用户代替目标用户回答。通过产品上下文门禁后立即创建最终 MDX 并写入已经确定的产品定义，不等待全部研究完成。

## 领域信息选择

人物通用设定只规定身份、事件、目标、资源、限制、经验、偏好、风险和替代结果等信息维度；具体字段由产品领域决定。旅行可以询问出发地、假期、预算和景观偏好，办公应询问任务、文件、协作者和系统，金融应询问资金、风险、账户和决策约束。不得把任一具体案例、软件、搜索词、地点或对象写成跨领域标准。

具体信息只有在能解释当前行为、判断、反馈或产品需求时才保留。为显得真实而堆砌无关品牌、地点或人口细节，同样视为不合格。

## 材料路径

- 默认路径是 Agent 模拟：通过相互隔离的虚拟用户 Agent 形成原始反馈。
- 用户提供访谈、评论、工单、问卷或行为记录时，使用材料综合路径。
- 同时具备 Agent 反馈和用户材料时，使用混合路径，分别保留来源并综合归纳。
- 行业资料、竞品资料和团队判断只用于设计研究问题、情境和候选差异，不直接代写用户反馈。

## 材料综合路径

把材料拆成可追溯的最小反馈单元：`feedback_id`、来源、匿名用户或样本范围、场景、原始观察、归纳解释、支持程度。原始观察与归纳解释必须分开。

优先按 JTBD、触发场景、行为和决策方式聚类，保留冲突观察。每个目标用户在 research sidecar 中列出主要 `feedback_id` 与材料范围；正式报告只保留理解产品判断所需的来源说明。

支持程度：

- 高：多名用户的行为证据或多个独立来源一致支持；
- 中：有限样本支持，或陈述与部分行为相互印证；
- 低：单一来源、单次陈述或解释性推断。

## Agent 模拟路径

先建立无产品基线：原始目标、触发事件、第一选择、替代方案、时间/金钱/风险/关系成本以及失败后的降级或放弃路径。产品包含多个独立命题时，分别写明任务、行为前提、主要阻力和替代方式。

运行隔离 Agent 后，先整理逐名反馈和行为差异，再选择目标用户。完整 Agent 设定、命题测试和反馈索引写入 research sidecar；正式报告只保留理解人物和产品判断所需内容。所有结论仍须能在 sidecar 中回到原始反馈。

## 分类禁区

- 国家或地区是行为背景，不是用户类型；优先继承 `PRODUCT_DEFINITION` 或用户指定的市场语境，未指定时根据产品上下文确定并在研究范围中写明。
- 年龄、性别、职业、企业规模不能直接代替需求分类。
- 用户类型、使用场景、任务阶段和产品能力必须分开。
- 流程阶段或对产品的接受程度不能单独构成用户类型。
