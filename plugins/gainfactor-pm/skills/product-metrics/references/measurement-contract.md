# 指标测量契约

生成任何指标候选时读取。本文件区分候选比较所需的最小契约和最终落地所需的完整契约。

## 最小测量契约

每个进入候选比较的指标至少说明：

| 字段 | 要求 |
|---|---|
| 业务问题 | 这个指标帮助产品或业务判断什么 |
| 业务定义 | 用普通读者能理解的语言说明谁在什么条件下获得了什么结果 |
| 通俗公式 | 先用业务对象表达计算关系，不出现字段名或查询语法 |
| 统计主体 | 用户、账户、团队、任务、交易、内容或其他实体 |
| 统计窗口 | 自然周期及计算窗口 |
| 合格与排除 | 什么计入，什么不计入 |
| 数据需求 | 需要哪些实体、事件、状态和关联 |
| 可统计性 | `可统计 / 有条件可统计 / 当前不可统计` |
| 可衡量性 | `可衡量 / 有条件可衡量 / 当前不可衡量` |
| 主要风险 | 混杂、刷高、延迟或错误激励 |

用户确认主要指标前必须看到最小测量契约，不能只确认名称。

## 完整测量契约

最终主要、过程和底线指标必须使用稳定 ID，并补全：

- 指标名称、类型、要回答的业务问题、通俗定义和期望方向；
- 通俗业务公式、分子／分母或计数对象，以及一个简单计算示例；
- 数据实现所需的技术公式；
- 统计对象、纳入和排除条件；
- 去重、归因、时间窗口和异常处理；
- 业务实体、唯一标识、事件或状态、事件时间及必要属性；
- 数据来源、刷新频率、覆盖范围和责任人；
- 可统计性、可衡量性及验证证据；
- 基线、目标和阈值状态；
- 指标变化后的判断与行动；
- 可能的博弈、误读和副作用。

淘汰候选、虚荣指标和伪底线指标保留最小契约即可，不要求进入最终指标的数据实现详情。

“完整”是分析与实施完整性要求，不是门户正文的展示模板。不得把上述字段逐条转换成连续项目符号并平铺给普通读者。业务正文只选择帮助理解和决策的信息；其余内容集中进入明确标注的数据实施附录。

## 表达顺序

分析时按以下顺序完成；门户正文只展示前 6 项，数据实现统一进入附录：

1. **它回答什么问题**：一句话说明这个指标支持的产品判断；
2. **普通人如何理解**：用业务语言解释指标含义与变化方向；
3. **如何计算**：先给通俗业务公式；比率指标分别解释分子和分母；
4. **简单示例**：使用清楚标记为“示例”的小数字演示，不能让示例值看起来像真实基线；
5. **什么计入／不计入**：解释合格与排除条件；
6. **当前能否可靠使用**：合并说明可统计性、可衡量性和最重要缺口；
7. **数据团队如何实现**：字段、事件、ID、去重、归因、异常和回填规则统一写入数据实施附录。

业务解释和数据实现必须分层。`task_id`、`COUNT(DISTINCT ...)`、布尔字段、事件表和查询条件只能出现在“数据实现”层，不能作为普通读者看到的第一条公式。

业务正文中单个指标不得使用“标签：长段落”连续罗列完整契约。超过 5 个说明项、出现两个以上技术 ID，或一项超过 120 字时，必须移入数据实施附录或拆成短段落。

## 公式规则

每个指标同时保留两种公式：

- **通俗业务公式**：面向产品和业务读者，使用“明确采纳的任务数 ÷ 成功展示候选的任务数 × 100%”一类表达；
- **技术公式**：面向数据实施者，使用稳定 ID、字段、过滤、去重和归因条件表达。

门户正文优先展示通俗公式；技术公式放在该指标的“数据实现”小节。两种公式的统计对象、纳入排除和窗口必须一致。

- **计数**：符合条件的实体或事件去重数；
- **求和**：符合条件记录的数值字段总和；
- **比率**：符合条件的分子 ÷ 明确机会集合的分母；
- **时长**：结束时间 − 开始时间，并说明中断处理；
- **分布／分位数**：明确样本集合和 P50、P95 等方法；
- **复合指标**：说明组成、权重、归一化和缺失值处理。

不是比率的指标不强造分子和分母，但所有公式都必须明确对象、窗口、纳入排除、去重和异常处理，并能由相同输入稳定复算。

比率指标的通俗表达模板：

```text
指标名称
= 符合成功条件的对象数
÷ 获得该成功机会的全部对象数
× 100%
```

示例模板：

> 示例（非真实业务数据）：100 个任务成功获得候选，其中 35 个发生明确采纳，该指标为 35%。

## 数据定义

| 要素 | 定义要求 |
|---|---|
| 业务实体 | 用户、账号、组织、任务、订单、会话、内容或决策等 |
| 唯一标识 | 去重和关联使用的稳定 ID |
| 事件或状态 | 何时产生记录，什么状态代表有效 |
| 事件时间 | 发生、完成或快照时间 |
| 必要属性 | 计算和过滤所需字段及允许值 |
| 有效条件 | 什么情况下计入计数、分子或样本 |
| 排除规则 | 测试、作弊、机器人、重复、取消和异常等 |
| 分析维度 | 用户群、场景、版本、地区、渠道或风险等级 |
| 数据来源 | 事件流、业务表、模型日志、人工审核或外部系统 |
| 责任人 | 谁维护口径、质量和变更记录 |

## 可统计性门禁

检查：稳定 ID、真实事件、兼容粒度与窗口、跨系统关联键、数据访问与覆盖、缺失重复延迟回填、样本稳定性和复算一致性。

- `可统计`：当前数据足以稳定复算；
- `有条件可统计`：公式成立，但仍有事件、字段、权限、覆盖、样本或质量缺口；
- `当前不可统计`：关键对象、事件、关联或数据无法可靠获得。

## 可衡量性门禁

检查：价值代表性、长期方向、变化敏感度、混杂因素、关键子群、行动性和抗博弈性。

- `可衡量`：能够有效代表目标并支持行动；
- `有条件可衡量`：价值关系成立，但仍需基线、样本、因果或阈值验证；
- `当前不可衡量`：虽然可能算得出，但不能可靠代表目标。

容易统计不等于能够衡量。`当前不可统计` 或 `当前不可衡量` 的指标可以保留定义，但 Measurement Readiness 必须为 `unverified`，并写明建设或验证动作。

## 数值与证据

任何实际数值、基线、目标、阈值或行业基准必须同时说明：统计对象、样本范围、时间窗口、数据截止时间、计算口径、数据来源和证据日期。样本量、覆盖或质量不足时，标为 `假设值`、`建议值` 或 `待验证`，不得作为事实或门禁通过依据。
