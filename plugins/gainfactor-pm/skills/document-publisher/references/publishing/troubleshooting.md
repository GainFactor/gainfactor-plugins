# 发布故障处理

仅在源校验、导入、构建、门禁或预览实际失败后读取。

- 先标明失败阶段和最后达到的状态，保留日志中最具体的错误。
- 保留源 MDX、`.portal.json`、`.review.json` 和图片；不回滚或覆盖门户中其他文档。
- 区分“已导入但未构建”“已构建但门禁失败”“已验证但服务未启动”“服务运行但目标页面失败”。
- `serve out` 不会自动刷新源文件；内容变化后必须重新构建。
- 不手工修改 `out` 绕过构建，不用旧页面或可访问端口冒充本轮结果。
- 缺少 Python、Node.js、pnpm 或 Playwright 浏览器时，报告缺失依赖和可恢复的下一条命令，不自动更换包管理器。
- 门禁失败时报告具体 route、视口、主题和组件；修复后从失败阶段重新执行，不重复改写已通过的正文。
